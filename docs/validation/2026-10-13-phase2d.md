## Runtime 경계 수정

- Agent pool은 idle 연결 checkout/반환, 최대1초 checkout 대기와 context 취소, FIFO 반환을 사용한다. 5초 idle threshold 후 KEEP_ALIVE를 최대3초 기다리고 닫힌 slot을 회수한다. 대기 취소는 진행 중 owner의 연결을 닫지 않는다.
- upstream Blob 오류에도 완전히 읽은 chunks를 보존한다. Client에 partial chunks를 쓴 뒤 error를 반환하고 TCP transport는 flush하되 성공 NoNEXT를 보내지 않는다. handler error 및 terminator byte 상한 실패의 flush를 구분해 처리한다.
- Object/Text 조회도 request context를 Store의 cancellable lock/scan에 전달한다. Sample5M은 Engine.Close 이후 저장하지 않는다. counter·Interaction TTL bulk 정리는 order를 stable compact하며 pending sample 예산은 별도로 유지한다.
- 오류 callback/queue/cache/연결/조회에는 개수·byte 상한이 있다. 이것이 RSS hard cap, 네트워크 no-loss, 강제 syscall 중단 또는 목표 TPS를 보장하지는 않는다. writer heartbeat는 sampling/disk 작업과 독립적으로 유지하고 저장 close 뒤 해제한다.

Telegraf는 `--telegraf-config`(기본 `./conf/scouter-telegraf.xml`)의 현재 파일 READ와 정본 `TgConfig.getSampleContents()` embedded sample fallback을 연결한다. 기존 빈 파일은 빈 text로 유지하고 없는 file/parent만 fallback한다. 파일 READ·sample 반환과 metric ingest/configuration apply는 별개이며 후자는 미구현이다. alert script 파일 READ도 script 실행 지원을 뜻하지 않는다.

## 최종 통합 검증 상태

JDK8 NaN oracle variant 정정 이후 `make check`와 `make race`는 전체 package 및 build를 완료했고 exit 0이었다. 로그의 완료 결과도 확인했다. 전체 실행 스냅샷 이후 마지막 Interaction compaction production/test 변경은 ingest 전체 race PASS로 검증했다. 이후 최종 재빌드 binary로 Java56 네트워크·SIGTERM·동일 DB 재시작 통합이 PASS이며 artifact SHA와 현재 dist SHA가 일치한다.

기록은 실행 exit code, binary SHA, source/harness checksum, 실제 assertion과 종료 통계를 구분한다. `make storage-check`는 별도로 반복하지 않았다. 같은 원본 storage 양방향 tests를 전체 `make check`·`make race`에서 실행했다. 원본 DB oracle에는 JDK8 Scala compiler runtime이 추가로 필요하며 source/JDK 부재로 skip한 실행은 PASS가 아니다. remote CI 실행 결과는 별도다.

초기 전체 race는 JDK8 DecimalFormat의 기본 NaN `�`와 Java18 baseline `NaN`의 차이로 실패했다. 실제 JVM symbol을 확인하는 환경별 검증으로 정정한 뒤 전체 재실행이 통과했다. 이 차이는 wire만으로 추정하지 않으며 [local store 계약](../compatibility/local-store-query.md)에 기록했다.

최종 Java seed 통계는 Completed41/XLogs5/DroppedXLogs1/Rejected0/StorageErrors0, UDP36datagrams/41Packets/모든오류0, TCP Accepted4/ClientRequests107/Errors0/Active0이다. 재시작 TCP는 Accepted3/ClientRequests67/Errors0/Active0이며 수집 데이터 재송신 없이 조회했다. 작은 synthetic 검증의 계수이며 운영 무손실의 근거가 아니다. source/harness checksum은 report에 보관한다. 검증 binary는 당시 working tree의 개발 artifact이며 release artifact가 아니다.

완료 단위는 별도 commit으로 기록했다. 주요 통합 commit은 `322033d`(수집/sampling/aggregation), `7d0546f`(Runtime/READ dispatch), `caca02a`(TTL), `7a16fb0`(local READ), `9c01654`(metadata), `3ca895f`(DB READ), `d54391e`(Java56 harness), `04bbdff`(registry 회귀)다. 이 밖의 세부 commit은 여기에 옮기지 않았다.

## 남은 범위와 위험

- 관리·상태 변경45개, JVM 의존 READ5개, LDAP/raw login, custom/JVM handler/plugin/script 실행, HTTP/webapp/WebSocket, Telegraf ingest/apply, retention scheduler, Pulse/Kafka/Collector는 미구현 또는 이번 범위에서 제외했다.
- 실제 Eclipse RCP GUI, 전체 OSHI/instrumentation Agent 동작·Agent V2 process는 미검증이다. 기존 원본 클래스의 synthetic socket 통합 및 V2 framing tests와 구분한다.
- 운영 DB 복사본 이관·대규모 restart/crash recovery, 잘린 tail·index/data 불일치·disk full·retention과 열린 reader/writer, watermark·누락/중복·rollback은 후속 gate다.
- Charset UTF-8와 동일 timezone을 전제로 한다. Java 고정24시간 날짜 계산과 원본 결함을 보존한 조회 의미는 일반 calendar/정상 집계와 다를 수 있다. 의도된 defensive 오류·path/symlink·bounded query 차이는 기능별 계약에 기록한다.
- 공유 호스트 전체를 전용 자원으로 가정하지 않는다. 지속 TPS·조회 병행·fsync/retention·CPU quota/RSS/I/O·p95/p99·drop/reject·종료 잔여 측정은 하지 않았다. 목표 처리량·무손실 운영·production readiness는 입증되지 않았다.
